# سیستم تحلیل مالی و سرمایه‌گذاری

نسخه اولیه قابل اجرا برای تحلیل یک سهم، با فملی به‌عنوان نمونه. Python 3.11+ و بدون وابستگی خارجی.

## اجرا

دستورها را در پوشه اصلی مخزن اجرا کنید:

```bash
python -m financial_system --demo
```

فایل `output/report.html` را در مرورگر باز کنید. خروجی عددی در `output/analysis.json` ذخیره می‌شود. گزارش فارسی، راست‌به‌چپ و بدون نیاز به اینترنت است.

**تمام اعداد نمونه ساختگی‌اند؛ قیمت، سود و ارزش‌گذاری واقعی فملی نیستند.** روزهای نمونه هم تقویم رسمی معاملات نیستند.

برای تحلیل داده خودتان:

```bash
python -m financial_system --prices data/private/prices.csv --fundamentals data/private/fundamentals.json --output output
python -m unittest discover -s tests -v
```

## قابلیت‌های فعلی

- بازده ۱، ۵، ۲۰ و ۶۰ جلسه معاملاتی، با قیمت تعدیل‌شده.
- حجم روز نسبت به میانگین دقیقاً ۲۰ مشاهده قبلی؛ هشدار در نسبت حداقل ۲.
- بیشترین افت از قله تا کف در کل دوره ورودی.
- ارزش بازار، EPS، P/E، P/B، حاشیه سود خالص و نسبت بدهی‌ها به دارایی‌ها.
- کنترل تکرار تاریخ، عدد نامعتبر، قیمت نامثبت، سازگاری ترازنامه و تاریخ انتشار گزارش.
- گزارش HTML و خروجی JSON، همراه با منبع و تاریخ اطلاعات.

## قرارداد داده

CSV باید ستون‌های زیر را داشته باشد؛ نمونه در `data/demo/prices.csv` است:

| ستون | تعریف |
|---|---|
| date | تاریخ میلادی ISO به فرم YYYY-MM-DD |
| close_irr | قیمت پایانی تعدیل‌نشده، ریال به ازای سهم |
| adjusted_close_irr | قیمت پایانی تعدیل‌شده، ریال به ازای سهم |
| volume | تعداد سهام معامله‌شده، عدد صحیح نامنفی |

فقط جلسات واقعی را وارد کنید. داده‌ها مرتب می‌شوند؛ تاریخ تکراری رد می‌شود. تعدیل، صحت تقویم جلسات و نبود شکاف در داده را واردکننده باید کنترل کند. قیمت‌ها به نماد فایل مالی تعلق داشته باشند؛ CSV نماد جداگانه ندارد.

فایل مالی JSON مطابق `data/demo/fundamentals.json`:

| فیلد | تعریف |
|---|---|
| symbol / company | نماد و نام شرکت |
| source / price_source | منبع مالی و قیمت؛ ترجیحاً شناسه یا نشانی گزارش |
| adjustment_method | روش تعدیل قیمت؛ افزایش سرمایه و سود نقدی را روشن کنید |
| period_end / available_on | پایان دوره مالی و تاریخ واقعی دسترسی به گزارش، میلادی ISO |
| basis / currency | در این نسخه فقط TTM و IRR |
| data_kind | synthetic برای نمونه یا user_provided برای داده واردشده |
| revenue_irr / net_income_irr | درآمد و سود خالص ۱۲ ماه منتهی به پایان دوره، به ریال |
| equity_irr / assets_irr / liabilities_irr | اقلام ترازنامه در پایان همان دوره، به ریال |
| shares_outstanding | تعداد سهام در تاریخ قیمت، متناسب با EPS محاسباتی |

ارقام «میلیون ریال» کدال باید پیش از ورود در ۱٬۰۰۰٬۰۰۰ ضرب شوند. سود و درآمد باید از یک دامنه گزارشگری، مثلاً هر دو تلفیقی یا هر دو شرکت اصلی، باشند. برای TTM، دوره‌های مالی را بدون هم‌پوشانی تجمیع کنید. در این نسخه تجمیع خودکار انجام نمی‌شود. کاربر باید تعداد سهام را برای افزایش سرمایه‌ها کنترل کند.

## روش و محدودیت‌ها

- بازده n جلسه = قیمت تعدیل‌شده آخر / قیمت تعدیل‌شده n مشاهده قبل − ۱. داده ناکافی با null نمایش داده می‌شود.
- قیمت تعدیل‌شده به‌خودی‌خود تضمین بازده کل نیست؛ پوشش سود نقدی به روش منبع وابسته است.
- ارزش بازار = قیمت تعدیل‌نشده × تعداد سهام. EPS = سود خالص TTM / تعداد سهام فعلی؛ این EPS محاسباتی لزوماً EPS حسابرسی‌شده نیست.
- P/E در زیان یا سود صفر و P/B در حقوق صاحبان سهام نامثبت محاسبه نمی‌شود. نسبت با مخرج صفر و حجم با میانگین صفر نامشخص است.
- بیشترین افت عددی صفر یا منفی است. نوسان‌گیری روزانه و هزینه معاملات لحاظ نشده است.
- رد گزارش با تاریخ دسترسی بعد از آخرین قیمت، فقط یک کنترل اولیه زمانی است؛ موتور بک‌تست و داده تاریخی نقطه‌به‌نقطه هنوز نداریم.
- هشدار حجم به‌تنهایی توصیه خرید، اثبات ورود پول هوشمند یا تشخیص دستکاری نیست.
- اتصال زنده به TSETMC/کدال، مقایسه شاخص، رتبه‌بندی سهام، پرتفوی و یادگیری ماشین هنوز پیاده‌سازی نشده‌اند.

## معماری و مسیر توسعه

`analytics.py`: اعتبارسنجی و محاسبات؛ `report.py`: نمایش؛ `__main__.py`: رابط خط فرمان. ورودی فایل از تحلیل و نمایش جداست تا دریافت‌کننده‌های داده واقعی بعداً اضافه شوند.

۱. بررسی دسترسی واقعی TSETMC و کدال؛ ذخیره داده خام، شناسه منبع، واحد و زمان دریافت.
۲. تطبیق داده فملی، تعدیل افزایش سرمایه و سود نقدی، کنترل کیفیت و مقایسه با شاخص.
۳. پایگاه داده تاریخی، پرتفوی و رتبه‌بندی با معیارهای شفاف؛ سپس بک‌تست بدون استفاده از اطلاعات آینده.
۴. مدل‌سازی مالی پروژه‌ها و بعد مدل‌های آماری، پس از آماده شدن داده قابل‌اتکا.

## نگهداری اطلاعات

مخزن عمومی است. اطلاعات شخصی، پرتفوی واقعی، رمز، توکن و داده دارای محدودیت انتشار را در آن ثبت نکنید. `.env`، `data/private/` و خروجی‌ها در `.gitignore` هستند. این نسخه هیچ کلید، حساب کاربری، احراز هویت، سرویس وب یا درخواست شبکه‌ای ندارد. اتصال‌ها و اسرارشان باید در مرحله بعد جدا طراحی شوند.
